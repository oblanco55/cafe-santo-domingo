# ORDEN F2-4 — Panel de administración UI (perfil: desarrollador-frontend)
LEE docs/DISENO.md y PLAN-F2.md. Usa SOLO src/components/ui y tokens de color. Breve; un archivo por llamada; informe máx. 10 líneas. Si un paso falla 2 veces, DETENTE.
HECHOS: API admin bajo /api/admin/** (F2-3): metrics, users (GET, PATCH [id]), creations (GET, GET [id]), legal (GET, PUT [slug]), ai/presets, ai/providers (GET, POST, PATCH [id], DELETE [id], POST [id]/test), settings (GET, PUT). auth() en '@/auth' expone session.user.role. Lee las rutas reales con `ls -R src/app/api/admin` antes de empezar.
1. Protección: src/app/admin/layout.tsx (server): si no hay sesión → redirect('/login'); si role !== 'admin' → notFound(). Añade /admin al matcher del middleware si hace falta. Layout con SiteHeader y navegación lateral (en móvil: pestañas horizontales con scroll) a: Resumen, Usuarios, Creaciones, Textos legales, IA, Ajustes.
2. SiteHeader: si role === 'admin', muestra enlace "Administración" → /admin.
3. /admin (Resumen): tarjetas (usuarios totales, nuevos 30 días, creaciones 30 días, errores) + reparto por modalidad y por plataforma (barras simples con CSS, sin librerías) + creaciones por día (lista o barras). Aviso text-warning si no hay ningún proveedor de IA configurado ("Las creaciones usan el modo simulado").
4. /admin/usuarios: buscador, tabla (móvil: tarjetas) con nombre, correo, rol, estado, creaciones, fecha; acciones Hacer admin / Quitar admin, Desactivar / Activar (confirmación con window.confirm), mensaje de error de la API si se intenta sobre uno mismo; paginación.
5. /admin/creaciones: filtros (modalidad, estado), tabla con fecha, usuario, modalidad, título, estado (error en text-danger), modelo; clic → detalle /admin/creaciones/[id] con la entrada (lista legible) y la salida (reutiliza ResultView en modo lectura) o el mensaje de error.
6. /admin/legal: lista de documentos; /admin/legal/[slug]: inputs título y Textarea Markdown (monoespaciado, alto), vista previa al lado (≥ md) o debajo, versión y "última actualización"; Guardar → PUT; feedback "Guardado".
7. /admin/ia: lista de proveedores (etiqueta, tipo, modelo, clave enmascarada, activo, por defecto, prioridad) con acciones Probar conexión (muestra ok/latencia o error), Editar, Eliminar (confirmación). Formulario "Añadir proveedor": Select de presets (rellena tipo, baseUrl, modelo), etiqueta, baseUrl (editable si custom/ollama), modelo, clave (type=password; al editar, vacío = no cambiar), activo, por defecto, prioridad. Texto de ayuda: "Si no configuras ninguno, se usa Claude con ANTHROPIC_API_KEY del servidor o el modo simulado".
8. /admin/ajustes: límite de creaciones por 10 min y creaciones gratis al mes (inputs numéricos) → PUT settings.
9. Markdown: usa una librería pequeña y segura (marked + isomorphic-dompurify, o react-markdown sin rehype-raw). Instálala.
10. Tests: tests/e2e/admin.spec.ts — usuario normal → /admin da 404; usuario cuyo correo está en ADMIN_EMAILS (configura ADMIN_EMAILS en playwright.config.ts webServer env con un correo de prueba) → ve Resumen, edita Términos y la versión sube, añade proveedor "Custom" con clave y la tabla muestra solo la máscara.
11. npx tsc --noEmit ; npm run lint ; npm test ; npm run build ; npm run test:e2e.
12. OBLIGATORIO: git add -A (sin .env) && git commit -m "feat(F2-4): panel de administración" && git push origin main.
